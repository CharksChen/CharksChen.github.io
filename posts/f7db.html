1. 审题方法论（5 分钟定胜负）

考试最常见的丢分不是"不会写"，而是"没读懂题就开写"。前 5 分钟决定整道题的成败。

1.1 开写前必须回答的 6 个问题

每道题打开后，先在草稿纸/注释里写下这 6 个答案，再动手写代码：

1.2 读题"三遍法"

遍数 读什么 目的
第1遍 只读 Description.md 理解题目在干什么
第2遍 读 main.cpp 找出所有被调用的函数和期望的输出
第3遍 读 .h/.hpp 抄下所有需要实现的函数签名

你的真实教训：周14电子设备题，你用 name() 字符串比较代替 typeid/dynamic_cast，就是因为没读题目要求"COUNT_N 必须使用 dynamic_cast"。

1.3 从 main.cpp 逆向推导函数行为

关键规则：main.cpp 里是 cout << func() → 你就 return，不要在函数里 cout。
main.cpp 里是 func()（没 cout）→ 说明函数自己负责输出。

4. 提交前自检清单（90 秒扫一遍）

每道题提交前过一遍这个清单，能避免 80% 的低级错误。

4.1 编译检查

  • [ ] 能编译通过，0 error 0 warning
  • [ ] 所有非 void 函数都有 return
  • [ ] 类声明后有分号 };
  • [ ] 头文件有保护 #ifndef 或 #pragma once
  • [ ] include 了所有用到的头文件

4.2 功能检查

  • [ ] 用样例输入跑过，输出和样例逐字符一致
  • [ ] 检查空输入/边界情况（0、1、空、最大值）
  • [ ] 检查负数处理（如果有负数输入）

4.3 输出格式检查

  • [ ] 行末没有多余空格
  • [ ] 每行末尾有换行（最后一行也要）
  • [ ] 小数位数正确（fixed << setprecision(n)）
  • [ ] 没有多余的空行
  • [ ] 大小写正确

4.4 内存检查

  • [ ] 所有 new 都有对应的 delete
  • [ ] new[] 配 delete[]，new 配 delete
  • [ ] 有指针成员的类写了深拷贝三件套
  • [ ] 赋值运算符有自赋值检查
  • [ ] 基类析构是 virtual

4.5 题目要求检查

  • [ ] 没有修改题目给的函数签名
  • [ ] 题目要求的特定语法（typeid/dynamic_cast/循环/sort）都用了
  • [ ] 实现了所有要求的函数（没有遗漏）

5. 内存安全清单（最高频致命错误）

你的真实错误分析显示，内存相关错误是最致命的。这一节专门解决。

5.1 sizeof 陷阱（你的真实错误！）

规则：永远不要对指针用 sizeof！用专门的 size 变量记录数组大小。

5.2 delete 后不 erase（你的真实错误！）

5.3 new/delete 配对表

分配方式 释放方式 记忆口诀
new int delete p 单个 new 配单个 delete
new int[100] delete[] p 数组 new 配 delete[]
new MyClass delete p 对象和基本类型一样
new MyClass[5] delete[] p 对象数组也是 delete[]
new int*[rows] delete[] mat 二维先删每行再删行指针

5.5 常见内存错误对照

现象 原因 检查方法
double free 浅拷贝，两个对象指向同一块 检查有没有写深拷贝
段错误 空指针/越界/悬空指针 加 if (p != nullptr) 检查
堆损坏 memcpy 字节数算错 用循环代替 memcpy
内存泄漏 new 了没 delete 检查每个 new 是否有对应 delete
use after free delete 后继续使用 delete 后立即置 nullptr

格式要求 代码写法 易错点
元素间空格，末尾无 if(i>0) cout<<" "; 容易写成每个后都加空格

7. 常见代码陷阱（基于你的真实错误）

这些是你实际犯过的错误，考前重点看。

7.1 非 void 函数不 return（你的真实错误！）

判断方法：看 main.cpp 里怎么调用——cout << func() 就 return，func() 就自己 cout。

7.2 不遵守题目要求的语法（你的真实错误！）

规则：题目要求用 dynamic_cast 就不能用 typeid，反之亦然。读题时标记出来。

7.3 注释掉代码而非修复（你的真实错误！）

规则：不要注释掉代码假装它不存在。写不出来的部分也要写一个能编译的版本。

7.4 数组越界访问（你的真实错误！）

7.5 算法过于复杂（你的真实错误！）

规则：写代码前先想 1 分钟"有没有更简单的方法"。能用数学公式就不用二维数组。

8. 易混淆概念对比表

8.1 前置 ++ vs 后置 ++

8.2 深拷贝 vs 浅拷贝

浅拷贝（默认） 深拷贝（手动写）
指针成员 复制指针地址（两个指向同一块） new 新内存 + 逐个复制
后果 double free / 互相干扰 各自独立
何时需要 类里只有值类型 类里有 new/指针成员
怎么写 不用写（编译器默认） 拷贝构造 + 赋值运算符 + 析构

8.3 override vs overload vs hide

8.4 virtual vs 纯虚

虚函数 纯虚函数
语法 virtual void f(); virtual void f() = 0;
基类能否实例化 能 不能（抽象类）
派生类必须实现 不必须 必须（否则派生类也抽象）
基类能否有实现 能 不能（C++11 可以 = 0 后在类外定义）

8.5 const 指针 vs 指针常量

8.6 dynamic_cast vs typeid

dynamic_cast typeid
用途 向下转型，安全访问派生成员 判断对象实际类型
语法 Derived* d = dynamic_cast<Derived*>(base); typeid(*p) == typeid(Derived)
失败表现 返回 nullptr 返回 false
要求 基类至少一个 virtual 基类至少一个 virtual（多态类型）
适用场景 需要访问派生类特有成员 只需判断类型，不访问成员

8.7 函数模板 vs 类模板

8.8 new vs malloc

new malloc
返回类型 正确类型的指针 void*（要强转）
调用构造函数 是 否
失败行为 抛异常 bad_alloc 返回 NULL
C++ 推荐 ✅ ❌（考试不用）

附：基于你真实错误的 TOP 5 修复清单

这 5 个错误是你实际犯过的，考前必须练到不再犯。

排名 错误 修复方法 练习题
1 sizeof(指针) 当数组大小 永远用 size 变量，用循环不用 memcpy 周8 IntArray
2 非 void 函数不 return 看 main 怎么调用决定 return 还是 cout 周14 电子设备
3 delete 后不 erase delete + erase 配对 周14 电子设备
4 不用题目要求的语法 读题时标记"必须用 XX" 周14 电子设备
5 尾随空格/多余换行 用 if(i>0) cout<<" " 周8 IntArray

考前建议：把这 5 个错误对应的题重做一遍，每题限时，确保不再犯同样的错误。
